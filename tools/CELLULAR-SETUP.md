# Cellular plans

Public pages use a dated, crawlable snapshot generated from public sources only.
No reseller link, reseller code, registration link or customer information is shipped.
The shared WhatsApp floating button remains, but the plan CTA goes to `index.html#contact`.

## Activate reviewed server sync

1. Apply `supabase/migrations/202610050001_cellular_plans.sql` to the existing Electroshop Supabase project.
2. Deploy `electroshop-sync-cellular` with both `index.ts` and `parser.mjs`, or paste `tools/electroshop-sync-cellular-deploy.ts` into a single-file dashboard function editor (generated by `node tools/build-cellular-deploy.mjs`). Keep JWT verification enabled. The function independently requires `is_electroshop_admin()`.
3. Test unauthenticated/ordinary-user rejection, private proposal RLS and public catalogue read.
4. Set `syncEnabled: true` in `cellular-config.js` and bump its import version in both consumers.
5. Open `shop-cellular-admin.html` after signing in through the existing shop admin. Sync each provider, review every card, then approve.

Sync is manual on purpose: public source changes are proposals, not automatic price publications.
Failed/partial fetches never alter published data. Proposals expire after two hours, and publishing
rejects a concurrent catalogue change. Partner uses public CMS plan terms, not its authenticated
checkout API. Only regular public sales plans are included, not dealer/government/private plans.
Pelephone reads both desktop/mobile lists and all more-info conditions. 019 reads its full
019mobile.co.il cellular catalogue, not the three featured cards on 019.co.il. The checked
snapshot contains 10 Pelephone, 5 Partner lobby and 12 019 plans. Prices and duration text
are per-plan source facts, not a generic promotion/multi-line claim. Public pages never show
editorial inconsistency warnings. The 019 source may refuse automated server requests; in
that case sync fails safely and retains the published catalogue instead of falling back to
the incomplete homepage. Verify source access from the deployed function before activation.
If a provider moves additional cards to a new endpoint, update and test the parser before publishing.

## Refresh committed HTML / SEO snapshot

Run `node tools/refresh-cellular-snapshot.mjs`, review `cellular-data.json`, then
`node tools/build-cellular-pages.mjs` and `node tools/generate-sitemap.mjs`.
For a manual refresh when 019 refuses automated access, export its public `.item_pack`
cards from the browser and pass their HTML path with `--019-html <path>`. Do not export
account/agent pages, bypass access controls, or include registration URLs in public output.
Do not run refresh automatically at build time: changing a remote marketing page must not silently
publish unreviewed pricing. The database catalogue takes precedence in the browser after activation;
the HTML fallback retains its actual verification date if the database is unavailable.

Use only public, code-free sources. Never add a reseller URL to configuration, logs, HTML or fixtures.
